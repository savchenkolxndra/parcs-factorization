# Паралельна факторизація числа методом пробних дільників на PARCS

Лабораторна робота з дисципліни «Хмарні обчислення»: система [PARCS-Python](https://github.com/Hummer12007/parcs-python) у Google Cloud, послідовний і паралельний алгоритми розкладу натурального числа N на прості множники методом пробних дільників.

## Ідея

**Послідовний алгоритм.** Вилучаємо множник 2, далі перебираємо непарні d = 3, 5, 7, … поки d ≤ ⌊√m⌋, де m – поточний залишок; кожен знайдений дільник вилучаємо повністю. Якщо в кінці m > 1, це просте число. У найгіршому випадку (N просте або N = p·q з близькими p, q) перевіряється ≈ √N / 2 кандидатів, тобто час O(√N).

**Паралельний алгоритм (map-reduce).**

1. Майстер вилучає множник 2 і отримує непарне m, межу L = ⌊√m⌋ і кількість непарних кандидатів C = (L − 1) / 2 (d = 3 + 2j, j = 0 … C − 1).
2. Номери кандидатів діляться на k рівних неперервних діапазонів: воркер i отримує j ∈ [C·i/k, C·(i+1)/k). Передаються лише три числа: m і межі діапазону.
3. **Map:** воркер перебирає свій діапазон і повертає дільники m, які в ньому знайшов (знайдений дільник одразу вилучається з локальної копії m).
4. **Reduce:** майстер сортує всі знайдені дільники й ділить на них m за зростанням; залишок > 1 – просте число, більше за L.

**Чому розклад правильний.** Кожне просте p ≤ L, що ділить m, лежить в одному з діапазонів і буде знайдене. Воркер може повернути й складене d, якщо його прості множники лежать у *попередніх* діапазонах, але в reduce до моменту обробки d усі ці менші прості вже вилучено, тож d більше не ділить залишок. Після всіх кандидатів у залишку немає простих ≤ L, отже він або 1, або одне просте > L (два таких дали б добуток > m).

Кандидати мають однакову вартість, тому статичного рівномірного поділу достатньо. Обсяг комунікації не залежить від N.

**Обмеження.** Паралельна версія завжди перевіряє весь діапазон до √m, бо воркер не знає дільників з інших діапазонів. Для чисел із малими множниками (`input/smooth_63bit.txt`) послідовна версія закінчує за мить, а паралельна – ні. Тому основні заміри зроблено для найгіршого випадку – напівпростого числа з близькими множниками.

## Структура

| Шлях | Призначення |
|---|---|
| `solution/factorization_parallel.py` | паралельна версія для PARCS (Python 2.7 і 3) |
| `solution/factorization_sequential.py` | послідовна версія: локально з командного рядка або як задача PARCS на майстрі |
| `input/` | вхідні числа (одне число у файлі, рядки з `#` – коментарі) |
| `tests/test_factorization.py` | перевірка обох версій проти `sympy.factorint` |
| `tools/local_run.py` | запуск PARCS-рішення локально без кластера |
| `tools/gcp_up.sh`, `tools/gcp_down.sh` | створення й видалення кластера в Google Cloud |
| `tools/run_measurements.sh` | серія замірів через API майстра → `results.csv` |
| `tools/summarize.py` | таблиця середніх, прискорення, ефективності та графік `speedup.png` |

## Запуск у Google Cloud

Усе робиться з **Google Cloud Shell** (кнопка `>_` у консолі Google Cloud) – там уже є `gcloud`, нічого ставити не треба.

1. Створи проєкт у консолі Google Cloud і підключи оплату (free trial / студентські кредити). Запам'ятай `PROJECT_ID`.
2. У Cloud Shell:
   ```bash
   git clone https://github.com/<твій-логін>/parcs-factorization && cd parcs-factorization
   bash tools/gcp_up.sh PROJECT_ID 4 europe-central2-a ТВОЯ_IP   # IP свого ПК: https://ifconfig.me
   ```
3. Через 2–3 хвилини відкрий `http://MASTER_IP:8080/workers` – має бути 4 воркери.
4. Заміри (3 прогони; послідовна + 1, 2, 4 воркери):
   ```bash
   bash tools/run_measurements.sh http://MASTER_IP:8080 input/semiprime_62bit.txt results/semiprime_62bit 3 "1 2 4"
   python3 tools/summarize.py results/semiprime_62bit/results.csv
   ```
5. **Обов'язково** видали кластер, бо VM коштують грошей, поки існують:
   ```bash
   bash tools/gcp_down.sh PROJECT_ID europe-central2-a
   ```

Задачу можна надіслати й вручну через веб-інтерфейс (`Add Job`: файл рішення + вхідний файл), результат – на сторінці `Jobs`.

## Безпека

PARCS приймає й виконує код без пароля, тому `gcp_up.sh` відкриває порт 8080 лише для твоїх IP-адрес, а VM створюються без сервісного акаунта. Образ `hummer12007/parcs-node` сторонній і працює на Python 2.7 – тримай кластер увімкненим лише на час роботи.
